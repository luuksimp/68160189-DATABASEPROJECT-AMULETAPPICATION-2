# จุดประสงค์
  1. จุดประสงค์หลัก (Main Objective)
  เพื่อศึกษา ออกแบบ และพัฒนา แพลตฟอร์มตลาดกลางซื้อขายพระเครื่องออนไลน์ (Thai Amulet Marketplace Platform) ที่มีระบบฐานข้อมูล (SQL Database) ประสิทธิภาพสูง รองรับการทำงานของผู้ใช้ทุก     กลุ่ม ทั้งผู้ซื้อ ผู้ขาย และผู้ดูแลระบบ
  2. จุดประสงค์ด้านเทคนิคและการแก้ปัญหา (Technical & Problem-Solving Objectives)
  - เพื่อแก้ปัญหาพระเก๊และการหลอกโอนเงิน: โดยการพัฒนาระบบตัวกลางถือเงิน (Escrow Payment System) และระบบยืนยันตัวตนผู้ขาย (KYC) เพื่อเพิ่มความปลอดภัยและสร้างความน่าเชื่อถือในวงการพระเครื่อง      ออนไลน์
  - เพื่อสร้างระบบจัดการข้อมูลพระเครื่องอย่างเป็นระบบ: ออกแบบโครงสร้างฐานข้อมูล relational database ให้รองรับการค้นหาและกรองข้อมูลแบบละเอียด เช่น การคัดกรองตามวัด, พระเกจิอาจารย์, ปี พ.ศ.,       เนื้อพระ และการตรวจเช็กใบรับรองพระแท้
  - เพื่อฝึกฝนและประยุกต์ใช้ทักษะทางเทคโนโลยี: ได้แก่ การจัดการฐานข้อมูล MySQL, การเขียนโปรแกรมฝั่งเซิร์ฟเวอร์ด้วย PHP, การใช้ Git/GitHub ในการควบคุมเวอร์ชันงาน และการ Deploy เว็บไซต์บน         เซิร์ฟเวอร์จริง (Angsila)
  3. จุดประสงค์ต่อผู้ใช้งาน (User-Centric Objectives)
  - สำหรับผู้เช่าบูชา (Buyers): เพื่อให้มีพื้นที่ซื้อขายพระเครื่องที่มั่นใจได้ว่าจะได้รับพระแท้ตรงปก และไม่เสียเงินฟรีหากเกิดข้อผิดพลาด
  - สำหรับผู้ขาย/เซียนพระ (Sellers): เพื่อเปิดโอกาสให้ร้านค้ามีหน้าร้านออนไลน์มาตรฐาน จัดการสต็อกสินค้าได้ง่าย และเพิ่มความน่าเชื่อถือผ่านเครื่องหมายยืนยันตัวตน (Verified Badge)

# ขอบเขตฟีเจอร์ที่มีในเว็ปไซต์
1. หน้าเข้าสู่ระบบและสมัครสมาชิก (Auth & Profile)
   - 1.1 หน้าสมัครสมาชิก (Register)
     - ข้อมูลทั่วไป:
       - ชื่อผู้ใช้ (Username): สำหรับใช้เข้าสู่ระบบ
       - อีเมล (Email) / เบอร์โทรศัพท์ (Phone): สำหรับติดต่อและแจ้งเตือน
       - รหัสผ่าน (Password / Confirm Password): สำหรับยืนยันความปลอดภัย
       - ประเภทบัญชี (Role): ตัวเลือกเลือกระหว่าง "ผู้ซื้อ (Buyer)" หรือ "ผู้ขาย (Seller)"
     - ส่วนยืนยันตัวตนผู้ขาย(KYC - สำหรับผู้ขาย):
       - ชื่อ-นามสกุลจริง (Full Name): ตรงตามบัตรประชาชน
       - ช่องอัปโหลดรูปบัตรประชาชน (ID Card Image): สำหรับตรวจสอบตัวตน
       - ช่องอัปโหลดหน้าสมุดบัญชี (Bank Book Image): สำหรับรับเงินโอน
       - เลขที่บัญชีธนาคาร & ชื่อธนาคาร (Bank Account Details): สำหรับระบบโอนเงิน
   - 1.2 หน้าเข้าสู่ระบบ (Login)
     - ชื่อผู้ใช้ หรือ อีเมล (Username / Email)
     - รหัสผ่าน (Password)
2. หน้าสำหรับผู้ขาย (Seller Dashboard & Listing)
   - 2.1 หน้าลงขายพระเครื่อง (Add New Amulet)
     - ข้อมูลหลัก:ชื่อพระเครื่อง (Name): เช่น พระสมเด็จวัดระฆัง พิมพ์ใหญ่
       - หมวดหมู่ (Category): Dropdown เลือก (พระเหรียญ, พระผง, พระกรุ, เครื่องราง ฯลฯ)
       - พระเกจิอาจารย์ (Monk/Creator): เช่น หลวงปู่ทวด, หลวงพ่อกวย
       - ชื่อวัด (Temple): เช่น วัดช้างให้, วัดโฆสิตาราม
       - ปี พ.ศ. ที่สร้าง (Year Created): เช่น 2505
       - เนื้อพระ / วัสดุ (Material): เช่น เนื้อทองแดง, เนื้อผงพุทธคุณ, เนื้อนวโลหะ
       - สภาพพระ (Condition): เช่น สวยแชมป์, ผ่านการใช้
     - การขายและการรับประกัน:
       - ราคาเช่าบูชา (Price): ช่องกรอกจำนวนเงิน (บาท)
       - ข้อมูลใบรับรอง (Certificate Info): ช่องกรอกเลขใบรับรอง / ระบุสถาบันที่ออกใบรับรอง
       - เงื่อนไขการรับประกัน (Guarantee Policy): เช่น รับประกันพระแท้ตลอดชีพ คืนเงินเต็มจำนวน
       - รายละเอียดเพิ่มเติม (Description): ช่องพิมพ์ข้อความอธิบายตำหนิ ประวัติ หรือรายละเอียดอื่นๆ
     - รูปภาพ (Media Upload):
       - ช่องอัปโหลดรูปภาพหลายมุมมอง: รูปด้านหน้า (รูปหลัก), ด้านหลัง, ด้านข้าง/ขอบ, และรูปโค้ด/ตำหนิ
3. หน้าสำหรับผู้ซื้อและหน้าหลักเว็บ (Buyer & Marketplace)
   - 3.1 หน้าฟีดและค้นหา (Marketplace / Catalog Feed)
      - ช่องค้นหาและตัวกรอง (Search & Filter Bar):
        - ช่องค้นหาด้วยข้อความ (Search Keyword): พิมพ์ค้นหาชื่อพระ หรือชื่อวัด
        - ตัวกรองหมวดหมู่ (Category Filter): เลือกดูเฉพาะประเภทพระที่สนใจ
        - ตัวกรองช่วงราคา (Price Range): กำหนดราคาต่ำสุด - สูงสุดตัว
        - กรองสถานะใบรับรอง (Has Certificate): ติ๊กเลือกเฉพาะรายการที่มีใบรับรอง
      - การแสดงผลการ์ดสินค้าบนหน้าฟีด (Amulet Card):
        - รูปภาพหลัก (Primary Image)
        - ชื่อพระเครื่อง + ปี พ.ศ.
        - ราคาเช่าบูชา
        - ป้ายสัญลักษณ์ยืนยันตัวตนผู้ขาย (Seller Verified Badge)
        - ปุ่มกดดูรายละเอียด / ปุ่มกดสั่งซื้อ
   - 3.2 หน้ารายละเอียดพระเครื่อง (Product Detail Page)
      - ส่วนแสดงรูปภาพ: รูปภาพขยายใหญ่ + Gallery รูปมุมต่างๆ (หน้า/หลัง/ขอบ)
        - ส่วนข้อมูลพระเครื่อง: แสดงรายละเอียดทั้งหมดที่ผู้ขายกรอกไว้ (ชื่อ, วัด, เกจิ, ปี, เนื้อ, เงื่อนไขรับประกัน)
        - ส่วนข้อมูลผู้ขาย: ชื่อร้านค้า/ผู้ขาย, คะแนนรีวิว (Rating), สถิติการขาย
        - ปุ่มดำเนินการ (Action Buttons):
        - ปุ่ม "เช่าบูชาทันที (Buy Now)"
        - ปุ่ม "ติดต่อผู้ขาย / สอบถาม"
  4. หน้าชำระเงินและจัดการออเดอร์ (Escrow & Order Management)
    - 4.1 หน้าสั่งซื้อและชำระเงิน (Checkout Page)
       - ข้อมูลการจัดส่ง (Shipping Address): ชื่อผู้รับ, เบอร์โทรศัพท์, ที่อยู่จัดส่งพัสดุ
       - ช่องทางชำระเงิน (Payment Options): แสดงเลขบัญชีธนาคารกลางของเว็บ (Escrow)
       - ช่องอัปโหลดสลิปโอนเงิน (Payment Slip Upload): สำหรับแนบหลักฐานการโอนเงิน
       - วัน-เวลาที่โอน (Transfer DateTime): ช่องระบุเวลาตามสลิป
    - 4.2 หน้าติดตามสถานะคำสั่งซื้อ (Order Tracking Page)
       - สถานะรายการ (Order Status Timeline):
         - รอตรวจสอบชำระเงิน -> กำลังจัดส่ง -> จัดส่งแล้ว/รอการตรวจสอบ -> สำเร็จ
       - ช่องแสดงเลขพัสดุ (Tracking Number): สำหรับผู้ซื้อนำไปเช็กกับบริษัทขนส่ง
       - ปุ่มกดยืนยันได้รับสินค้า (Confirm Receipt): กดเมื่อได้รับพระและตรวจสอบเรียบร้อยแล้ว เพื่อให้ระบบปล่อยเงินให้ผู้ขาย
  5. หน้าผู้ดูแลระบบ (Admin Dashboard)
     - ช่องอนุมัติผู้ขาย (KYC Approval): ปุ่มกดดูรูปบัตรประชาชน/สมุดบัญชี และปุ่ม "อนุมัติ / ปฏิเสธ"
     - ช่องตรวจสอบสลิปโอนเงิน (Payment Verification): ปุ่มกดดูสลิป และปุ่ม "ยืนยันยอดเงินเข้า"
     - ช่องปล่อยเงินให้ผู้ขาย (Release Escrow Funds): ปุ่มกดอนุมัติโอนเงินเข้าบัญชีผู้ขาย เมื่อผู้ซื้อมั่นใจและกดยืนยันรับของแล้ว

# ตลาดพระเครื่อง (PHP + MySQL)

หน้าตาอิงเทมเพลต "ตลาดพระเครื่อง" (โทนเขียว-ทอง) ใช้ฐานข้อมูลและฟีเจอร์เดิมทั้งหมด + หน้าใหม่ + ปรับให้เสถียรขึ้น

## ติดตั้งใหม่
1. XAMPP / Laragon (PHP 8.1+ และ MySQL/MariaDB)
2. คัดลอกโฟลเดอร์ไปไว้ที่ `htdocs/amulet-market`
3. phpMyAdmin → Import `database.sql`
4. คัดลอก `config.example.php` เป็น `config.php` แล้วแก้ user/password (`config.php` ไม่ถูกเก็บใน Git)
5. เปิด `http://localhost/amulet-market/`
6. (ไม่บังคับ) ใส่ข้อมูลตัวอย่าง 4 รายการจากเทมเพลต: `php tools/seed_demo.php`

## อัปเกรดจากเวอร์ชันเดิม (มีข้อมูลอยู่แล้ว)
1. **สำรองฐานข้อมูลก่อน**
2. Import `migration.sql` ใน phpMyAdmin (รันครั้งเดียว) — เพิ่มสถานะใหม่ ที่อยู่จัดส่ง ตารางรายการโปรด/กันเดารหัส และหมวด "พระกรุ"
3. เปิด `config.php` เพิ่มค่าจาก `config.example.php` ส่วน "ค่าเพื่อความเสถียร" (ถ้าไม่เพิ่ม ระบบใช้ค่าเริ่มต้นให้)

## ที่ปรับให้เสถียรขึ้น
- **ไม่โชว์ error/รหัสฐานข้อมูลบนเว็บ**: error ทั้งหมดลง log แล้วแสดงหน้าแจ้งที่เป็นมิตร (`APP_DEBUG=true` เฉพาะตอนพัฒนา); ต่อ DB ไม่ได้แสดงหน้า 503 ไม่ใช่ stack trace
- **Transaction ทุกขั้นตอนสำคัญ** (สั่งซื้อ, ชำระ, จัดส่ง, รับของ, ยกเลิก, รีวิว) ล็อกแถวด้วย `FOR UPDATE` แล้วเช็คสถานะซ้ำ และลองใหม่อัตโนมัติเมื่อชน deadlock — กดซ้ำ/สองคนกดพร้อมกันก็ไม่ซ้ำ ไม่ค้างครึ่งทาง
- **คำสั่งซื้อที่ไม่ชำระ** ถูกยกเลิกและปล่อยพระกลับมาขายอัตโนมัติหลัง `ORDER_HOLD_HOURS` (เดิมพระค้าง "จองแล้ว" ตลอดกาล); ยกเลิกแล้ว **เก็บประวัติ** แทนการลบแถว
- **UNIQUE + UPSERT**: รีวิวซ้ำ, สมัครซ้ำ, กดไลก์/โหวตรัว ไม่ทำให้เกิดหน้า error
- **กันเดารหัสผ่าน**: ผิด 5 ครั้งใน 15 นาที (ต่อชื่อผู้ใช้+IP) ต้องรอ
- **อัปโหลดรูป**: ตรวจชนิดจริง/ขนาดพิกเซล/ขนาดไฟล์, ลบไฟล์ทิ้งอัตโนมัติถ้าบันทึกฐานข้อมูลไม่สำเร็จ (ไม่เหลือไฟล์ขยะ)
- **เวลา**: PHP กับ MySQL ใช้ timezone เดียวกัน (Asia/Bangkok) "x ชั่วโมงที่แล้ว" ไม่เพี้ยน
- ปุ่มกันกดซ้ำ, จำกัดความยาวข้อมูลทุกช่อง, query ฟีดไม่ยิง DB ซ้ำรายโพสต์, ตลาดแบ่งหน้า
- `.htaccess` ซ่อน `config.php` / `*.sql` / `.git`, ใส่ security headers พื้นฐาน

## หมายเหตุ / ข้อจำกัด
- การชำระเงินเป็นการ **จำลอง** — ใช้งานจริงต้องเชื่อม payment gateway / escrow (ตอนนี้ผู้ซื้อกด "ชำระ" เองได้)
- ยังไม่มีหน้า Admin ตรวจข้อพิพาท/ยืนยันตัวตน: แก้ `users.Verification_Status` และ `reviews_disputes` ผ่าน phpMyAdmin
- ตั้ง Admin: `UPDATE users SET Role='Admin' WHERE Username='...'`
- ไม่เก็บเลขบัญชีธนาคาร/บัตรประชาชนในเว็บ (ช่อง `users.Bank_Account` ยังมีในตารางแต่ไม่ถูกใช้)
- ขึ้นเว็บจริงควรใช้ HTTPS (cookie เซสชันจะตั้ง `Secure` ให้อัตโนมัติ) และสำรองฐานข้อมูลสม่ำเสมอ
